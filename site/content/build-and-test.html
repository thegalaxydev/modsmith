Build and test a Minecraft mod

How to build a Fabric or NeoForge mod in Modsmith, run it in a test client or dedicated server, apply changes to the running game and debug it. This guide assumes a project created as in Getting started.

Build the mod

Open More actions (the ⋯ button at the right of the toolbar) and choose Build. Modsmith runs the project's own Gradle wrapper with a suitable JDK and shows the output in the Tasks panel. Compile errors are listed in Problems and link to the line in the editor. Clean build runs a clean build, and Run data generation runs the loader's data generation task.

The built JAR is in the project's build/libs folder, as with any Gradle mod project. You do not need to build before launching: launching builds what it needs.

Run configurations

Projects created with the test profiles starter have two run configurations, chosen in the list at the left of the toolbar:

  • Test Client runs the project's current code in a Minecraft client.
  • Dedicated Server checks that the project works on a dedicated server, where client-only code must not run.

Each configuration has its own game folder under .modsmith/instances, with its own mods, options and worlds, so test worlds never mix with your normal Minecraft installation. The Configs page (Run configurations) lets you change memory, Java, JVM and game arguments, turn the development bridge on or off, test the built release JAR instead of the development setup, or duplicate a configuration.

Launch the game

  1. Choose Test Client and press Launch client. The toolbar shows Building, then Starting.
  2. The Client tab shows the game. On Windows, and on Linux with X11 or XWayland, it is embedded in the tab; Move to a separate window releases it, and Embed here brings it back. Click the game to type into it and press Esc in the game to release the mouse.
  3. Press Stop when you are done. The game is asked to close normally, so the world is saved.

For the Dedicated Server, Modsmith asks you to accept the Minecraft EULA once for that server, then starts it. The Console shows its output and has an input line for server commands.

Apply changes without restarting

While the game runs, Apply changes in the toolbar lists what you edited since launch:

  • Code compiles the project and hot-reloads changed Java method bodies. It needs Hot reload and debugger turned on for the configuration; if it is off, Turn on and restart does that for you.
  • Assets reloads textures, models, sounds and translations.
  • Game data reloads recipes, tags, loot tables and advancements.

Some changes cannot be applied to a running JVM, such as adding or removing fields or methods, or changing mixins. Modsmith lists the reasons, changes nothing in the game, and offers to restart. See Java hot reload for the full list.

Debug with breakpoints

  1. Turn on Hot reload and debugger for the configuration on the Configs page, and launch it.
  2. Open a Java file and click in the gutter to the left of the line numbers to set a breakpoint.
  3. Press the debug button in the toolbar to open the Debug panel, then Start debugging. The first time, Modsmith downloads the Java debugger (about 3 MB) and restarts Java support.
  4. When the game reaches the breakpoint, the panel shows the call stack and variables, and Evaluate runs expressions such as player.getName(). Use F5 to continue, F10 to step over, F11 to step into and Shift+F11 to step out.
  5. Stop debugging detaches and leaves the game running.

The debug port accepts one connection at a time, so stop debugging before using Apply changes for code.

Inspect the running game

With the development bridge on (it is part of the starter test configurations and is never included in your release JAR), the Inspector shows the block or entity you are looking at, with quick actions to give items and run commands, and the Client tab can take screenshots of the game.

Automate checks

  • Scenarios (Tests, scenarios) run scripted steps against a running game: commands, giving items, and checks on blocks, inventories, registry entries and log lines. New scenario opens a visual editor, and steps can be filled in from the game. When the game is not running, Run starts the configuration in a fresh test world and stops it afterwards; against a running game it runs in place. Scenarios can also name a server and players for multiplayer checks.
  • Multiplayer test… in More actions starts the dedicated server and up to four clients with separate player names, already connected.
  • Performance (Tests, performance) benchmarks a configuration on a fresh world and compares two results.

Common problems

  • Gradle fails before compiling. Usually a Java version mismatch; see Java problems.
  • Launch client is greyed out. The project's loader is not supported for launching, or a build is already running.
  • Apply changes says the game must restart. The change altered a class's structure; restart with Rebuild and restart.

More fixes are in Troubleshooting.
