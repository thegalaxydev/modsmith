Test your mod with other mods and modpacks

Most compatibility bugs only show up next to other mods. Modsmith lets each run configuration load its own set of extra mods, from Modrinth, CurseForge, JAR files or an entire modpack, without touching your project's build.

How test mods work

  • Extra mods belong to a run configuration, not to your mod's build. They are only copied into that configuration's isolated game folder.
  • Your project's own code and its build dependencies are always included.
  • Choose the configuration in the for list at the top of the Mods page before adding mods.

Add a mod from Modrinth or CurseForge

  1. Open Mods in the left rail and press Add mods.
  2. Choose Modrinth or CurseForge and search. Results are limited to your project's loader and Minecraft version, and show downloads, the client and server sides, and the license.
  3. Press Add, then Check compatibility. Modsmith resolves required dependencies, downloads every file with hash verification, and reads each mod's metadata for missing dependencies, version conflicts and known incompatibilities. Mods are also checked automatically when you press Play.

Each mod row shows No problems found or a short description of the problem. Select a mod to see why it is there (for example, which mod requires it), its source, license and which side it runs on. Switch a mod off with its toggle to test without it.

CurseForge search needs your own API key (Settings, Providers). Some CurseForge authors do not allow third-party downloads; Modsmith marks those mods, links to the file page, and asks you to download the file and use Provide downloaded file, checking it against the expected hash.

Add a local JAR

Press Import JAR on the Mods page and choose the file. Modsmith reads its metadata (mod ID, version, dependencies) and includes it in the compatibility check.

Import a modpack

  1. On the Mods page, under Modpacks, press Import a modpack….
  2. Under Add to, keep A new run configuration named after the pack, or pick an existing configuration.
  3. Search Modrinth or CurseForge, or press From a file… for a .mrpack or CurseForge .zip, and press Import.
  4. Press Play to download the mods and start the game. Your own mod always comes from the development build, even if the pack contains an older copy.

Imported mods appear in a group named after the pack, where each one can be switched off. Import the pack again to update it.

Link a modpack you already play

If you play a modpack in the CurseForge app, the Modrinth App or Prism Launcher, press Link a modpack folder…. Modsmith lists compatible packs it finds in those launchers' default folders, or press Choose a folder…. The folder is read every time the configuration launches and is never changed, and you can choose to copy its config folders into the test game.

Keep versions stable and update on purpose

Modsmith records the exact version of every test mod in modsmith.lock.json, and launches keep those versions until you update them. Under Updates on the Mods page:

  1. Check for updates lists mods with a newer version for your loader and Minecraft version, including dependencies.
  2. Untick any you want to keep, and press Preview changes to see which mods would change, be added or be removed, and any new or fixed problems. Nothing is written yet.
  3. Press Update. Modsmith records a rollback point.
  4. If something breaks, open Update history and press Roll back to return to the earlier versions.

Find the mod that causes a problem

When a crash or bug only happens with many mods installed, switch groups of mods off on the Mods page and relaunch. The Tests page also has a dependency-aware bisect tool that splits the mods into halves while keeping each mod together with its required dependencies.

Common problems

  • "Made for a different Minecraft version or loader." The file you added does not declare support for your project's version or loader. Pick a different version of the mod.
  • "Requires …" A required dependency is missing and could not be resolved. Add it from Modrinth or CurseForge.
  • "Already provided by the project; remove this copy." Your build already includes the mod (for example Fabric API), so the extra copy is not needed.
  • A pack fails in development but works for players. Turn on Release build for the configuration on the Configs page to test the built JAR the way players run it.
